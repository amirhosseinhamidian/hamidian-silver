# راهنمای طراحی پنل مدیریت گالری حمیدیان

دامنهٔ این راهنما رابط Admin است. کار جدید باید از الگوی سالم موجود در نزدیک‌ترین صفحه استفاده کند. ایرادهای قابل بازتولید مبنای اصلاح صفحه‌های موجودند. [گزارش طراحی MAR-04](../execution/reports/MAR-04.md)

## پوسته، صفحه و ناوبری

- مدیریت Sidebar دسکتاپ، نوار سریع موبایل، فاصلهٔ امن پایین و پرش به محتوای اصلی با AdminShell است. هر مسیر محتوایی یک عنصر main دارد و ریشهٔ صفحات استاندارد از admin-container استفاده می‌کند.
- فاصلهٔ افقی این قاب تا عرض ۷۶۷ پیکسل در هر سمت ۱۶ پیکسل و از ۷۶۸ پیکسل ۲۴ پیکسل است. عرض محتوا با admin-content-max محدود می‌شود. Loading همان قاب و دامنهٔ عرض صفحهٔ نهایی را به کار می‌گیرد.
- هدر صفحه عنوان، مسیر برگشت یا Breadcrumb در صفحات چندسطحی و اقدام اصلی مرتبط را ارائه می‌کند. دکمه‌ها و فیلترهای Toolbar روی عرض باریک به خط بعد می‌روند. عنوان بلند یا شناسه با bdi و شکستن متن در همان ظرف جا می‌گیرد.
- Tab و منو با هدف مدیر و زبان فارسی نام‌گذاری شوند. وضعیت انتخاب‌شده با نشانهٔ معنایی مانند aria-current همراه باشد. مسیر قدیمی و سطح مجوز از ناوبری و API تا مقصد بررسی شوند.

## توکن‌ها و دسترس‌پذیری

- تایپوگرافی Admin از Vazirmatn و رنگ، شعاع، سایه و فوکوس از tokens.css می‌آیند. رنگ وضعیت با برچسب یا متن همراه شود. رنگ متن و سطح، حالت Hover، Disabled و Focus روی زمینهٔ واقعی بررسی شوند.
- زبان سند fa و جهت نوشتار rtl است. از start و end منطقی برای فاصله‌گذاری استفاده شود. مبلغ، درصد و تاریخ از قالب‌بندهای موجود می‌آیند. URL، SKU و شناسه در متن فارسی با bdi یا جهت محلی مناسب جدا شوند.
- فوکوس صفحه‌کلید قابل دیدن بماند و ترتیب Tab با ترتیب عمل سازگار باشد. Dialog، BottomSheet و Select موجود را با نام و عنوان قابل دسترس به کار ببرید. بستن Dialog و بازگشت فوکوس به کنترل بازکننده بررسی شود. حرکت و انتقال بصری به prefers-reduced-motion احترام می‌گذارند.

## فرم و انتخابگر

- هر کنترل نام قابل دسترس و برچسب فارسی دارد. متن راهنما برای معنا و پیام خطا برای رفع مشکل کنار همان فیلد قرار گیرند. Placeholder نمونهٔ ورودی است. اجباری بودن، واحد، بازهٔ مجاز و اثر صفر یا خالی در فیلدهایی که رفتار را تغییر می‌دهند روشن باشد.
- از FormField و FormControl و برای مبلغ از MoneyInput موجود استفاده کنید. در فرم طولانی، گروه‌بندی بر اساس کار مدیر و Wizard موجود نقطهٔ شروع است. هنگام ذخیره، وضعیت انتظار مشخص شود. ارسال تکراری کنترل و ورودی‌ها پس از خطای قابل رفع حفظ شوند.
- شناسهٔ فنی و تنظیمات کم‌مصرف در بخش پیشرفته قرار می‌گیرند. مقدارهای تولیدشده مثل Slug باید از API هم اعتبارسنجی شوند. عملیاتی با اثر مالی یا غیرقابل بازگشت باید نام روشن، مجوز مناسب و توضیح نتیجه داشته باشد.
- برای زمان‌بندی از DualCalendarPicker استفاده کنید. تغییر تقویم، زمان متناظر را حفظ کند. بازهٔ گزارش از نظر تاریخ و منطقهٔ زمانی با منبع اعتبارسنجی شود. برای انتخاب محصول، دسته و برند از انتخابگر موجود، جست‌وجوی سمت سرور، صفحه‌بندی و نگه‌داشتن انتخاب‌ها بین صفحات استفاده کنید. دامنهٔ دستهٔ مستقیم یا درختی در فرم مشخص باشد.

## جدول، گزارش و داشبورد

- DataTable برای ارائهٔ جدولی استاندارد، ResponsiveDataView برای نمایش قابل تطبیق با صفحهٔ باریک و TableScrollRegion برای جدول سفارشی عریض در دسترس‌اند. جدول عنوان قابل دسترس، سرستون و واحد دارد. پیمایش افقی داخل همان ناحیه و قابل دسترسی با Tab است.
- مرتب‌سازی، فیلتر و صفحه‌بندی باید روی همان جامعه و قرارداد سرور عمل کنند. برگشت از Drill-down فیلتر و صفحهٔ قبلی را حفظ کند. لینک عملیات بر اساس مجوز، نام و مقصد روشن دارد.
- ابتدا شاخص‌های لازم برای تصمیم نمایش داده شوند. نمودار برای روند یا مقایسه است و جدول برای مقادیر دقیق. عنوان نمودار، واحد، بازه و راهِ خواندن مقدار اصلی را نشان دهد. معنا به رنگ متکی نباشد. تراکم محتوا روی موبایل و متن بلند واقعی بررسی شوند.
- صفر معتبر، دادهٔ ناموجود و پوشش ناقص در KPI، نمودار، جدول و Export هم‌معنا بمانند. زمان رخداد، منطقهٔ زمانی، منبع، مخرج و تفاوت انتساب، تخفیف و پرداخت با قرارداد گزارش هماهنگ باشند.

## وضعیت‌ها و تحویل

- Skeleton جای محتوای مورد انتظار را نشان دهد. حالت خالی دربارهٔ محدودهٔ فعلی توضیح بدهد و اقدام لازم را در صورت وجود ارائه کند. خطا مشخص کند چه عملی ناموفق بوده و مسیر تلاش دوباره یا برگشت را نشان دهد. موفقیت یا هشدار مهم با متن و معنای قابل دسترس اعلام شود.
- بررسی دستی صفحات تغییرکرده در ۳۲۰، ۷۶۸ و ۱۴۴۰ پیکسل، مسیر Tab، کنتراست و خوانایی، حالت خالی/خطا، Select یا Dialog باز، Overflow صفحه، و نقش‌های مرتبط را پوشش دهد. شاهد بررسی با همان SHA در گزارش تسک ثبت شود. معیارهای مشترک برای دامنهٔ تغییر به‌کار می‌روند.
