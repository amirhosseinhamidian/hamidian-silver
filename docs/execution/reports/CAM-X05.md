## سهمیه و فروش

سهمیهٔ هر محصول در یک کمپین میان واریانت‌های آن مشترک است. سهمیهٔ جدید تا پیش از شروع کمپین برای محصول مشمول قانون ذخیره‌شده تعریف می‌شود. سقف در زمان تعریف و ظرفیت استفاده‌نشده در زمان افزایش با موجودی قابل فروش انبار پیش‌فرض سنجیده می‌شوند. تنظیم سهمیه و تغییر زمان‌بندی کمپین برای جلوگیری از هم‌پوشانی سهمیه‌های یک محصول در بازه‌های متداخل هماهنگ می‌شوند. هر اصلاح پنل با نسخهٔ رکورد کنترل می‌شود.

در پنل از **کمپین ← قانون و کوپن ← سهمیه و فروش دستی** محصول را انتخاب کنید. سقف، فروش قطعی سایت، فروش دستی، رزرو، ماندهٔ سهمیه و موجودی قابل فروش نمایش داده می‌شوند. فرم تعداد کل فروش دستی را با نسخه، شناسهٔ مدیر و زمان ذخیره می‌کند. اگر کالای فروش دستی از انبار سایت خارج شده، موجودی واریانت از بخش انبار اصلاح می‌شود.

در سفارش کمپینی، سهمیه و موجودی در یک تراکنش رزرو می‌شوند. اگر تعداد سبد از سهمیهٔ یک قانون بیشتر باشد، موتور قیمت‌گذاری قانون‌های واجد شرایط دیگر را بررسی می‌کند. قیمت تازه در Checkout نیازمند تأیید مشتری است. سقف بودجه و تعداد استفاده از قانون CM-02 پیروی می‌کند.

تأیید قطعی پرداخت سهمیه را مصرف می‌کند. لغو و انقضا رزرو سهمیه را همراه با رزرو موجودی آزاد می‌کنند. رد رسید و شکست قطعی آخرین تلاش پرداخت، سهمیه را آزاد می‌کنند و رزرو موجودی تا مهلت جاری برقرار می‌ماند. پاسخ نامشخص یا وجود تلاش دیگری که هنوز باز است، سهمیه را نگه می‌دارد. تلاش دوبارهٔ همان سفارش در مهلت موجودی و بازهٔ فعال کمپین، نیازمند رزرو مجدد سهمیه است و قیمت ثبت‌شده حفظ می‌شود. اگر سهمیه در دسترس نباشد، مشتری می‌تواند سفارش قبلی را در حساب کاربری لغو کند و به سبد برگردد تا قیمت جاری را تأیید کند. مرجوعی پس از تأیید، حتی با بازگشت کالا به موجودی، شمار خرید قطعی و سهمیهٔ مصرف‌شده را تغییر نمی‌دهد.

کارت و صفحهٔ محصول فروش‌رفته و مانده را از API می‌خوانند. ماندهٔ قابل خرید کمینهٔ ماندهٔ سهمیه و موجودی قابل فروش است. با صفر شدن مانده، قیمت همان کمپین از کارت، واریانت و Offer ساختاریافته حذف می‌شود. خرید با قیمت جاری تابع موجودی محصول است. شمار سهمیه برای هر صفحه به‌صورت دسته‌ای خوانده می‌شود. زمان پاسخ روی دادهٔ نمایندهٔ تولید اندازه‌گیری نشده است.

بلوک زیر PostgreSQL آزمایشی را روی یک پورت آزاد لوکال راه می‌اندازد و پس از پایان اجرای بلوک، همان کانتینر را جمع می‌کند.

```bash
(
  cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" || exit 1
  cam_x05_db="$(docker run -d --rm \
    -e POSTGRES_USER=hamidian -e POSTGRES_PASSWORD=cam_x05_local \
    -e POSTGRES_DB=hamidian_cam_x05_test -p 127.0.0.1::5432 postgres:18.6-alpine)" || exit 1
  trap 'docker stop "$cam_x05_db" >/dev/null' EXIT

  for attempt in {1..30}; do
    docker exec "$cam_x05_db" pg_isready -q -h 127.0.0.1 -U hamidian -d hamidian_cam_x05_test && break
    sleep 1
  done
  docker exec "$cam_x05_db" pg_isready -h 127.0.0.1 -U hamidian -d hamidian_cam_x05_test || exit 1
  cam_x05_address="$(docker port "$cam_x05_db" 5432/tcp)" || exit 1
  export DATABASE_URL="postgresql://hamidian:cam_x05_local@${cam_x05_address}/hamidian_cam_x05_test"

  pnpm db:generate &&
  pnpm exec prisma migrate deploy &&
  pnpm api:test:e2e --runInBand 'campaign-quota|promotion-checkout|campaign-lifecycle'
)
```
