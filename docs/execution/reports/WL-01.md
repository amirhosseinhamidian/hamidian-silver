# WL-01 — سیاست و شبیه‌ساز پاداش خرید

وضعیت `IN_REVIEW` است. مرحله از `2f2539a` روی `seo-fix` آغاز شد. مدیر پروژه موفقیت تست‌های محلی را گزارش کرد. نتیجهٔ تفکیکی تست‌ها جداگانه ثبت نشده است. SHA کامیت در انتظار ثبت است.

## محاسبه

- تخصیص، جمع مبلغ کالاهای واجد شرایط پس از تخفیف مستقیم، اعتبار تسویه‌شده و وجه نقدی بازپرداخت‌شده را می‌گیرد. ارسال و آبکاری در سطر کالا وارد نمی‌شوند. سبد پرداخت‌نشده، لغوشده یا کاملاً مرجوع‌شده پاداش ندارد. در مرجوعی جزئی می‌توان با همان نسخه و ارقام ثبت‌شده بازماندهٔ پاداش را محاسبه کرد. ثبت اصلاحی به دفتر کیف پول وابسته است.
- مصرف، مبلغ کالاهای واجد شرایط پس از تخفیف مستقیم و پیش از مصرف اعتبار را می‌گیرد. کمینهٔ ماندهٔ معتبر، سقف ثابت پلکان، سقف درصدی و سقف مصرف کمپین، حداکثر مصرف است. دستهٔ مجاز و کالای یا دستهٔ مستثنا برای هر مسیر جدا تعریف می‌شوند. استثنا بر مجاز بودن مقدم است. همراهی با کوپن هم برای تخصیص و مصرف جدا تنظیم می‌شود.
- حد پایین هر بازه شامل و حد بالا خارج از بازه است. وقتی حد بالا خالی باشد، بازه تا سقف مبلغ قابل پشتیبانی ادامه دارد. از قواعد فعال و منطبق، بالاترین اولویت انتخاب می‌شود. هم‌پوشانی قواعد با اولویت یکسان برای مبلغ و مرتبهٔ یکسان رد می‌شود. مرتبهٔ خرید از تعداد خریدهای نهایی قبلی در ورودی شبیه‌سازی به دست می‌آید. قواعد شمارش واقعی خرید و هم‌زمانی هنگام اتصال به گردش سفارش اعمال می‌شوند.
- سقف مستقل پاداش و سقف مجموع مشوق‌ها برای سفارش، مشتری در دوره و کل دوره اعمال می‌شوند. دوره ماه تقویمی تهران است. ورودی دوره باید مصرف بودجهٔ قبل از سفارش نمونه را در همان ماه و با احتساب نسخه‌های قبلی بدهد. مجموع مشوق‌های جدید شامل تخفیف مستقیم کالا و ارسال، تعهد جدید پاداش و مشوق‌های جدید دیگر است. تسویهٔ اعتباری که قبلاً صادر شده دوباره به هزینهٔ دوره اضافه نمی‌شود. رسیدن به سقف پاداش جدید را محدود می‌کند و تخفیف مستقیم ثبت‌شده را بازنویسی نمی‌کند. هزینهٔ تأمین برای برآورد سود موجود نیست.

## نسخه و دسترسی

API مدیریتی از مسیر `/api/v1/reward-policies` در دسترس است.

| مسیر | کارکرد |
| --- | --- |
| `GET /` و `GET /{version}` | فهرست ۲۵تایی و جزئیات نسخه |
| `GET /active` | نسخهٔ منتشرشده‌ای که از زمان اثر آن گذشته است |
| `POST /` | ثبت پیش‌نویس ثابت با `requestId` یکتا |
| `POST /simulation` | شبیه‌سازی مدل سبد روی نسخهٔ انتخاب‌شده |
| `POST /{version}/publish` | انتشار همان نسخه و ثبت زمان اثر و شناسهٔ مدیر |

خواندن و شبیه‌سازی به `finance.read` نیاز دارند. ایجاد و انتشار هر دو مجوز `finance.read` و `finance.write` می‌خواهند. انتشار با قفل ردیف انجام می‌شود. Retry همان نسخه، زمان و مدیر انتشار را حفظ می‌کند. در لحظهٔ انتشار، وجود شناسه‌های کالا و دستهٔ سیاست فعال سنجیده می‌شود. زمان اثر به UTC ذخیره می‌شود و ثبت نسخه با زمان اثر گذشته رد می‌شود. زمان اثر خالی یعنی اثر در لحظهٔ انتشار. در زمان اثر مساوی، شمارهٔ بزرگ‌تر مقدم است. برای توقف، نسخهٔ غیرفعال منتشر می‌شود. اگر نسخهٔ فعال دیگری برای آینده زمان‌بندی شده باشد، توقف اضطراری فقط تا زمان اثر آن نسخه برقرار است.

تعریف هر نسخه بعد از ساخت قابل بازنویسی نیست. اگر دادهٔ پیش‌نویس نیاز به اصلاح دارد، نسخهٔ تازه ساخته می‌شود. شبیه‌ساز روی نسخهٔ قدیمی هم اجرا می‌شود و مبلغ تراکنش یا سفارش را تغییر نمی‌دهد. تغییرات این تسک به Checkout، سفارش‌های قبلی، مانده، Worker یا اعلان متصل نیستند. هیچ سیاستی با مهاجرت فعال نمی‌شود. ارقام ۳، ۵ و ۱۰ میلیون، نرخ‌ها و مهلت ۲۷۰ روز در آزمون‌ها نمونه‌اند. سیاست واقعی هنگام انتشار مدیر تعیین خواهد شد.

## اجرای محلی

```bash
pnpm contracts:generate && pnpm contracts:typecheck &&
pnpm db:validate && pnpm api:lint && pnpm api:typecheck &&
pnpm api:test --runInBand modules/reward-policies modules/promotions modules/audit
```

برای مسیر نسخه‌بندی، زمان اثر، انتشار هم‌زمان، جلوگیری از تاریخ گذشته و کنترل مجوز، یک PostgreSQL آزمایشی بسازید. Docker پورت آزاد محلی را انتخاب می‌کند.

```bash
(
  cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" || exit 1
  wl01_db="$(docker run -d --rm \
    -e POSTGRES_USER=hamidian -e POSTGRES_PASSWORD=wl01_local \
    -e POSTGRES_DB=hamidian_wl01_test -p 127.0.0.1::5432 postgres:18.6-alpine)" || exit 1
  trap 'docker stop "$wl01_db" >/dev/null' EXIT

  for attempt in {1..30}; do
    docker exec "$wl01_db" pg_isready -q -h 127.0.0.1 \
      -U hamidian -d hamidian_wl01_test && break
    sleep 1
  done
  docker exec "$wl01_db" pg_isready -h 127.0.0.1 -U hamidian -d hamidian_wl01_test || exit 1
  wl01_address="$(docker port "$wl01_db" 5432/tcp)" || exit 1
  export DATABASE_URL="postgresql://hamidian:wl01_local@${wl01_address}/hamidian_wl01_test"

  pnpm db:generate &&
  pnpm exec prisma migrate deploy &&
  pnpm api:test:e2e --runInBand reward-policies
)
```

تست واحد نقطهٔ قبل و روی سه مرز پلکان، تبدیل پاداش خام ۶۰۰ هزار به سقف ۵۰۰ هزار، مرتبهٔ اول تا سوم، استثناها، کسورات اعتبار و مرجوعی و اولویت قوانین را می‌سنجد. تست E2E پیش‌نمایش نسخهٔ پیش‌نویس، تکرار درخواست، انتشار نسخهٔ آینده، توقف با سیاست غیرفعال و بازتولید نتیجه از نسخهٔ قبلی را پوشش می‌دهد.
