# PD-03 — جست‌وجوی داخلی و نرمال‌سازی فارسی

وضعیت `IN_REVIEW` است. پیاده‌سازی از کامیت `fe2a3a4` روی `seo-fix` آغاز شد. نتیجهٔ E2E و Query Plan نسخهٔ پیشین PD-01 همچنان در گزارش همان تسک در انتظار ثبت است.

## تطبیق عبارت و رتبه‌بندی

- جست‌وجوی فهرست، Facet و پیشنهادها از قوانین مشترک PostgreSQL استفاده می‌کند. حروف عربی و فارسی ک و ی، ارقام فارسی و عربی و لاتین، نیم‌فاصله، خط تیره و فاصله‌های اضافه به شکل واحد خوانده می‌شوند. حروف لاتین به کوچک و صورت‌های سازگار Unicode به NFKC تبدیل می‌شوند. نمونهٔ `ＳＩＬＶＥＲ-RING ۹٢۵` به `silver ring 925` تبدیل می‌شود. [تابع Normalize در PostgreSQL](https://www.postgresql.org/docs/18/functions-string.html)
- واژه‌نامه در `catalog-search.ts` گروه‌های رایج مانند انگشتر و ring، گردنبند و necklace، دستبند و bracelet، گوشواره و earring، زنجیر و chain، نیم‌ست و half set، نقره و silver و ساعت و watch را تعریف می‌کند. عبارت اصلی حداکثر با سه شکل دیگر جست‌وجو می‌شود. تغییرات واژه‌نامه باید گروه‌های مشخص و تست دوطرفه داشته باشند.
- امتیاز پایه برای نام محصول ۱۲، اسلاگ ۱۰، SKU برابر ۹، نام برند ۶، اسلاگ برند و نام دسته ۵، اسلاگ دسته و ویژگی ۴ و توضیح کوتاه ۲ است. تطابق کامل، پیشوند و بخشی از عبارت به ترتیب ۶، ۴ و ۲ امتیاز اضافه می‌کنند. شباهت متنی امتیاز تکمیلی دارد و شکل مترادف ۰٫۴ امتیاز کمتر می‌گیرد. بهترین امتیاز هر محصول در ترتیب دخیل است. قاعدهٔ موجودی، Sort و ترتیب نهایی شناسه همچنان برای صفحه‌بندی اعمال می‌شوند.
- ویژگی‌ها از آخرین مقدار معتبر در تعریف فعال و دامنهٔ دسته خوانده می‌شوند. مقدار پاک‌شده از جست‌وجو کنار می‌رود. عدد ویژگی و عبارتی مانند `عیار 925` با مقدار دقیق مقایسه می‌شوند. تطابق تقریبی فقط برای عبارت دارای حرف و حداقل سه نویسه فعال است. کاراکترهای `%` و `_` در الگوی LIKE به‌صورت ورودی داده تفسیر می‌شوند. [رفتار تطبیق و ایندکس pg_trgm](https://www.postgresql.org/docs/18/pgtrgm.html)

## پیشنهاد و آمار

پیشنهاد بعد از مکث ۳۰۰ میلی‌ثانیه، با سقف ۸ محصول و چهار مورد برای هرکدام از دسته و برند ارائه می‌شود. کلیک یا انتخاب با صفحه‌کلید به همان مقصد می‌رود. پاسخ درخواست قبلی بعد از لغو در رابط اعمال نمی‌شود. هر فرایند API حداکثر سه درخواست پیشنهاد هم‌زمان اجرا می‌کند و هنگام پر بودن ظرفیت، وضعیت ۴۲۹ را به Storefront برمی‌گرداند.

فقط درخواست موفق صفحهٔ اولِ جست‌وجوی نتیجه در شمارش روزانهٔ UTC ثبت می‌شود. عبارت‌ها حداکثر از سه واژهٔ مصوب واژه‌نامه و عیارهای ۹۲۵، ۹۵۰ و ۹۹۹ ساخته می‌شوند. هر ورودی دیگر در `other` شمارش می‌شود. عدد کل و عدد بدون نتیجه در PostgreSQL اتمیک افزایش می‌یابند. متن آزاد، شناسهٔ کاربر، IP، URL و پیشنهادهای حین تایپ در این جدول ذخیره نمی‌شوند. این شمارش تفکیک کاربر یا Session ندارد.

## مهاجرت و اثر روی SEO

مهاجرت تابع نرمال‌سازی را به‌روز می‌کند، ایندکس‌های تابعی موجود را بازسازی می‌کند و ایندکس اسلاگ و جدول آمار را می‌افزاید. زمان بازسازی و قفل نوشتن باید در PostgreSQL آزمایشی بررسی شود. مسیرهای کنونی محصول، دسته و برند، لینک مقصد پیشنهاد، Canonical، Robots، Redirect، Sitemap و JSON-LD از همان قرارداد قبلی استفاده می‌کنند. [رفتار REINDEX در PostgreSQL](https://www.postgresql.org/docs/18/sql-reindex.html)

## اجرای دستی

```bash
pnpm contracts:generate &&
pnpm contracts:typecheck &&
pnpm api:lint && pnpm api:typecheck &&
pnpm api:test --runInBand modules/catalog &&
pnpm storefront:lint && pnpm storefront:typecheck &&
pnpm storefront:test
```

روی PostgreSQL آزمایشی جدا، پس از تنظیم `PD03_TEST_DATABASE_URL` اجرا کنید. روش تخصیص پورت آزاد در گزارش SEO-04 آمده است. [دستورهای PostgreSQL آزمایشی](SEO-04.md#بررسی-دستی)

```bash
DATABASE_URL="${PD03_TEST_DATABASE_URL:?}" pnpm exec prisma migrate deploy &&
DATABASE_URL="${PD03_TEST_DATABASE_URL:?}" pnpm api:test:e2e --runInBand 'catalog-(search|facets)'
```

برای مشاهدهٔ شمارش واژه‌ها در پایگاه آزمایشی پس از چند جست‌وجو، از گزارش فقط‌خواندنی استفاده کنید:

```bash
DATABASE_URL="${PD03_TEST_DATABASE_URL:?}" pnpm exec tsx --tsconfig apps/api/tsconfig.json \
  apps/api/scripts/catalog-search-report.ts 7
```

مدیر پروژه موفقیت تست‌های محلی API و Storefront را تأیید کرد. کامیت `775e5d1686af3a4b80f4184621170b09910ea37e` روی `seo-fix` ثبت شد. نتیجهٔ مهاجرت و E2E روی PostgreSQL در انتظار ثبت است. پوشش تازه شامل تطابق دو زبان و ارقام، اسلاگ، ویژگی عددی و مقدار پاک‌شده، ورودی wildcard، شمارش تجمیعی و محدودیت پیشنهاد است.
