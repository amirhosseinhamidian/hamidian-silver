# CX-05 — باشگاه مشتریان و تجربهٔ بازگشت

وضعیت `IN_REVIEW` است. پیاده‌سازی از `seo-fix@d0e1ad3` آغاز شد. پیش‌نیازهای `WL-06`، `RF-04` و `CX-01` در ردیاب تکمیل شده‌اند. موفقیت آزمون‌های محلی به گزارش مدیر پروژه ثبت شد و SHA در انتظار ثبت است.

## رفتار و تصمیم‌ها

- زبانهٔ «باشگاه مشتریان» در حساب کاربری ماندهٔ قابل مصرف، اعتبار در انتظار و مبلغ رزروشده را نشان می‌دهد. دو کارت پاداش خرید و پاداش معرفی، ماندهٔ قابل مصرف، در انتظار، رزروشده و منقضی هر منبع را از دفتر کیف پول می‌خوانند. مبلغ قابل استفاده در سفارش همچنان با قیمت و شرایط همان سبد در Checkout محاسبه می‌شود.
- یادآوری باشگاه از API اعلان کیف پول و تنظیم کنونی مشتری می‌آید. مبلغ و زمان دقیق انقضا به وقت تهران نمایش داده می‌شود. تاریخچه و تنظیمات در همان بخش کیف پول قابل دسترسی‌اند.
- کد و سه معرفی اخیر در باشگاه دیده می‌شوند. وضعیت اولین پرداخت و صدور اعتبار معرف مستقل‌اند. وضعیت قابل نمایش از بررسی پاداش می‌آید. امتیاز ریسک، دلیل داخلی، هویت و سفارش شخص معرفی‌شده در این نما نمایش داده نمی‌شوند. صدور و ثبت کد در مسیر فعلی معرفی انجام می‌شود.
- در پرداخت ناموفق یا نیازمند بررسی، باشگاه مسیر پیگیری همان سفارش را نمایش می‌دهد. وضعیت تلاش پرداخت در پاسخ مشتری فقط به شکل یک نشانگر ارائه می‌شود. جزئیات فنی درگاه در باشگاه نمایش داده نمی‌شوند.
- معرفی مزایا شامل شرایط پاداش خرید، پاداش معرفی، مصرف اعتبار و پیوند راهنمای هدیه است. طراحی توسعهٔ اختیاری VIP، تولد و پیشنهاد ویژه باید سه کلید مستقل، حالت پیش‌فرض خاموش و امکان غیرفعال‌سازی در پنل داشته باشد. برای تولد، دریافت اختیاری داده با رضایت جدا لازم است. رابط این مرحله از قابلیت‌های فعال فعلی استفاده می‌کند و پیامک تبلیغاتی ندارد.

## حریم خصوصی و بررسی

باشگاه داخل `/account` با متادیتای خصوصی باقی می‌ماند. درخواست‌ها بعد از ورود به API خصوصی و بدون کش می‌روند. خروج از حساب دادهٔ نمای باشگاه را می‌بندد. این مرحله مهاجرت ندارد. URL، Canonical، Robots عمومی، Sitemap و JSON-LD تغییر نکرده‌اند.

پوشش مرورگر وضعیت صفر، پاداش معلق و منقضی، بررسی معرفی، پرداخت ناموفق، نمایش زمان انقضا، عرض صفحه، دسترس‌پذیری و ورود را می‌سنجد. PostgreSQL ماندهٔ هر منبع و وضعیت مشتری هنگام بررسی، صدور و اصلاح پاداش معرفی را می‌سنجد.

در اجرای اولیه، Mock ترتیبی داشبورد برای درخواست سبد ذخیره‌شده پاسخی تعریف نکرده بود و درخواست کیف پول بدون Promise ماند. پاسخ‌ها بر اساس مسیر درخواست تعریف شدند و مدیر پروژه پس از اصلاح، پاس‌شدن آزمون‌ها را گزارش کرد.

```bash
  cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" || exit 1
  cx05_db="$(docker run -d --rm \
    -e POSTGRES_USER=hamidian -e POSTGRES_PASSWORD=cx05_e2e_local \

    docker exec "$cx05_db" pg_isready -q -h 127.0.0.1 -U hamidian -d hamidian_cx05_test && break
    sleep 1
  done
  docker exec "$cx05_db" pg_isready -h 127.0.0.1 -U hamidian -d hamidian_cx05_test || exit 1
  cx05_address="$(docker port "$cx05_db" 5432/tcp)" || exit 1
  case "$cx05_address" in 127.0.0.1:[0-9]*) ;; *) exit 1 ;; esac
  export DATABASE_URL="postgresql://hamidian:cx05_e2e_local@${cx05_address}/hamidian_cx05_test?schema=public"

  pnpm db:generate &&
  pnpm exec prisma migrate deploy &&
  pnpm api:test:e2e --runInBand 'wallet-ledger|referral-grants|referral-checkout|referrals'
)
```
