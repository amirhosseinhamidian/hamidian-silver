## تعریف و انتشار

در جزئیات یک کمپین پیش‌نویس، مدیر می‌تواند عنوان، توضیح، اسلاگ صفحه، نوع انتشار و قواعد مجموعه را تنظیم کند. مجموعهٔ خودکار دسته و زیردسته، برند، بازهٔ قیمت، ویژگی گزینه‌ای یا عددی و حداقل موجودی را از قواعد PD-01 می‌گیرد. مجموعهٔ دستی از اسلاگ محصولات به ترتیب ثبت‌شده استفاده می‌کند. دامنهٔ محصول مادر کمپین برای هر دو روش اعمال می‌شود. فقط محصول فعال با قیمت قابل فروش و موجودی قابل رزرو از انبار پیش‌فرض وارد مجموعه می‌شود. موجودی و قابلیت فروش اجزای بسته هم بررسی می‌شوند.

پیش‌نمایش تعداد از پرس‌وجوی مشترک کاتالوگ به دست می‌آید. ذخیرهٔ تنظیمات، نسخهٔ کمپین و تغییرات صفحه و جایگاه‌ها را همراه با شناسهٔ مدیر در تاریخچه ثبت می‌کند. تأیید و زمان‌بندی مجموعهٔ خالی انجام نمی‌شود. اگر موجودی یا قیمت پس از انتشار تغییر کند، API دوباره مجموعه را می‌خواند. محصولات خارج از شرایط کنار می‌روند. صفحهٔ بدون نتیجه وضعیت خالی را نمایش می‌دهد و بنر و Sitemap آن حذف می‌شوند.

## جایگاه‌ها و آدرس عمومی

هر کمپین می‌تواند در صفحهٔ نخست، دسته و محصول یک جایگاه تنظیم کند. دسته و محصول می‌توانند مقصد مشخص یا همهٔ صفحات همان نوع باشند. هر جایگاه بازهٔ شمسی تهران و اولویت خودش را دارد. در صورت خالی بودن زمان، بازهٔ اصلی کمپین به کار می‌رود. بنر به صفحهٔ کمپین لینک می‌دهد و با انقضا از صفحهٔ باز حذف می‌شود. نمایش جایگاه‌ها به گزینهٔ فعال بودن بنر در فرم اصلی کمپین وابسته است. کمپین‌های قدیمی فاقد صفحهٔ اختصاصی از همان بنر صفحهٔ نخست استفاده می‌کنند.

آدرس عمومی `/campaigns/{slug}` است. اسلاگ و نوع SEO پس از نخستین ذخیره ثابت می‌شوند. نوبت‌های تکرارشونده می‌توانند یک اسلاگ مشترک داشته باشند و انتشار آن‌ها در بازه‌های هم‌پوشان پذیرفته نمی‌شود. اسلاگ صفحهٔ موقت فقط برای همان کمپین رزرو می‌شود.

| وضعیت                                                    | پاسخ و سیاست SEO                                                                                                       |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| موقت فعال                                                | پاسخ ۲۰۰، Canonical صفحه، `noindex, follow`، خارج از Sitemap                                                           |
| موقت پایان‌یافته یا اسلاگ ناشناخته                       | پاسخ ۴۰۴                                                                                                               |
| تکرارشوندهٔ فعال با محصول                                | صفحهٔ اول قابل ایندکس و در Sitemap. پارامترهای ردیابی روی Canonical اثر ندارند.                                        |
| تکرارشوندهٔ پایان‌یافته با سابقهٔ انتشار یا مجموعهٔ خالی | پاسخ ۲۰۰ با حالت توضیحی، `noindex, follow` و خارج از Sitemap                                                           |
| پارامتر فیلتر و صفحه‌بندی                                | پارامتر فیلتر محصول تازه تولید نمی‌کند. صفحهٔ دیگر با Canonical خودش `noindex` است و صفحهٔ خارج از بازه پاسخ ۴۰۴ دارد. |

لینک محصولات و صفحه‌بندی در HTML قابل دنبال کردن‌اند. لینک‌ساز UTM موجود، آدرس عمومی صفحهٔ کمپین را می‌پذیرد. مسیرها و Redirectهای کاتالوگ، Canonical محصول و دسته، Robots سراسری و JSON-LD فعلی از همان مسیر موجود تولید می‌شوند. محتوای صفحهٔ کمپین تخفیف قطعی را از قیمت کالا استنباط نمی‌کند. Sitemap فقط صفحهٔ تکرارشونده‌ای را می‌گیرد که در لحظهٔ خواندن فعال و دارای محصول است. [مستندات Canonical در Google Search Central](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

خواندن، پیش‌نمایش، جایگاه و Sitemap در تراکنش‌های خواندن با مهلت مشخص انجام می‌شوند. خواندن معمول مجموعه حداکثر ۲۴ محصول در صفحه دارد و برای شمارش، ردیف محصول بارگیری نمی‌شود. جایگاه‌ها با ایندکس محل و مقصد و به ترتیب اولویت خوانده می‌شوند. هزینهٔ اجرا روی دادهٔ نمایندهٔ VPS اندازه‌گیری نشده است.

## اجرای دستی

```bash
pnpm contracts:generate && pnpm contracts:typecheck &&
pnpm api:lint && pnpm api:typecheck &&
pnpm api:test --runInBand modules/catalog modules/campaigns modules/growth-attribution &&
pnpm frontend:lint && pnpm frontend:typecheck &&
pnpm storefront:test route-policy.test.ts sitemap.test.ts campaign-banner.test.tsx &&
pnpm frontend:build
```

برای PostgreSQL، `CM03_TEST_DATABASE_URL` را روی پایگاه دادهٔ آزمایشی محلی تنظیم کنید.

```bash
DATABASE_URL="${CM03_TEST_DATABASE_URL:?}" pnpm exec prisma migrate deploy &&
DATABASE_URL="${CM03_TEST_DATABASE_URL:?}" pnpm api:test:e2e --runInBand 'campaign-landing|campaign-lifecycle|catalog-facets|promotion-checkout'
```

فرمان Playwright قواعد SEO، سه جایگاه، مقصد لینک و عرض صفحه را در پروفایل‌های دسکتاپ، تبلت و موبایل بررسی می‌کند.

```bash
pnpm storefront:test:e2e campaign-landing.spec.ts catalog-seo.spec.ts
```

در پنل محلی، یک کمپین پیش‌نویس با محصول موجود انتخاب کنید. عنوان، توضیح، قاعده و حداقل یک جایگاه بسازید، تعداد را پیش‌نمایش کنید و پس از فعال کردن گزینهٔ بنر در فرم اصلی، کمپین را تأیید و زمان‌بندی کنید. بنر را در صفحهٔ مقصد باز کنید و تغییر قیمت یا موجودی محصول را با همان آدرس بررسی کنید.
