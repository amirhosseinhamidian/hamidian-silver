# CM-05 — فروش و بازده اقتصادی کمپین

وضعیت `IN_REVIEW` است. این مرحله از `0bca317` روی `seo-fix` و پس از تأیید تطبیق PostgreSQL در GM-04 آغاز شد. مدیر پروژه موفقیت تست‌های محلی را گزارش کرد. نتیجهٔ تفکیکی تست‌ها و بازبینی پنل جداگانه گزارش نشده‌اند. SHA کامیت در انتظار ثبت است.

## گزارش و مبنای ارقام

با مجوز `finance.read` از نام کمپین در داشبورد رشد یا دکمهٔ عملکرد در پنل کمپین وارد گزارش شوید. هزینه‌ها و اصلاحیه‌های دستی به تاریخچهٔ موجود GM-04 با فیلتر همان کمپین پیوند دارند. بازه تا ۹۲ روز تقویمی تهران را پوشش می‌دهد. داده‌ها از یک Snapshot پایگاه داده خوانده می‌شوند.

| شاخص | تعریف |
| --- | --- |
| نشست، سفارش، خرید قطعی و وصول | منبع مشترک GM-04 و GM-03. نشست از اندازه‌گیری اختیاری مرورگر می‌آید و ممکن است ناقص باشد. رسید ردشده یا سفارش پرداخت‌نشده خرید قطعی محسوب نمی‌شود. |
| مشتری جدید | حسابی که نخستین سفارش پرداخت‌شده‌اش در فروشگاه در همان بازه به این کمپین منتسب است. زمان پرداخت و شناسهٔ سفارش ترتیب را تعیین می‌کنند. |
| CAC | هزینهٔ ثبت‌شدهٔ رسانه تقسیم بر تعداد مشتریان جدید، گرد شده به تومان. |
| ROAS | وصول قطعی پس از کسر بازپرداخت قطعی همان بازه تقسیم بر هزینهٔ ثبت‌شدهٔ رسانه. بازپرداخت خرید دورهٔ قبل در روز تأیید بازپرداخت لحاظ می‌شود. |
| تخفیف کالا و ارسال | ستون‌های ثابت رسید قیمت CM-02 برای سفارش‌هایی که در بازه پرداخت قطعی شده‌اند، به تفکیک کمپینی که تخفیف را اعمال کرد. فروش منتسب به کمپین UTM می‌تواند با کمپین تخفیف متفاوت باشد. |
| اعتبار مصرف‌شده، پاداش صادرشده و تعهد باز | هر کدام مقدار مستقل دارند. تا اتصال دفتر کیف پول در مرحلهٔ WL مقدار ناموجود نمایش داده می‌شود. جمع بودجه در این مرحله بر هزینهٔ رسانه و تعهد تخفیف استوار است. |

CAC و ROAS فقط با ثبت هزینهٔ مثبت و پوشش هزینه در همهٔ ترکیب‌های منبع و کانال دارای خرید قطعی محاسبه می‌شوند. CAC به دست‌کم یک مشتری جدید نیاز دارد. ثبت دستی ممکن است بخشی از هزینهٔ واقعی را پوشش دهد. هزینهٔ تأمین موجود نیست و سود خالص گزارش نمی‌شود. برای شناسه‌های قدیمیِ بدون مدل کمپین، شاخص‌های منتسب قابل مشاهده‌اند و تخفیف و بودجه ناموجودند.

## بودجه و حسابرسی

سقف و سهم برنامه‌ریزی‌شدهٔ کانال از CM-04 خوانده می‌شوند. هزینهٔ ثبت‌شدهٔ رسانه، جمع دفتر هزینه و اصلاحیه‌های آن در کل دورهٔ کمپین است. تخفیف تعهدشده بر اساس همان شرایط Checkout محاسبه می‌شود و مبلغ تعهد پرداخت‌نشده بخشی از آن است. انحراف کل برابر هزینهٔ ثبت‌شدهٔ رسانه به‌علاوهٔ تخفیف تعهدشده منهای سقف کل است. با مبلغ نامعلوم یا جمع منفی دفتر هزینه، انحراف نمایش داده نمی‌شود. گزارش بودجه به بازهٔ انتخابی محدود نمی‌شود.

تاریخچهٔ لغو از زمان لغو سفارش و تاریخچهٔ انتساب از Snapshot ثبت سفارش می‌آیند. هر سطر کمپین تماس اول، آخر و منتخب را با مدل و نسخهٔ سیاست نشان می‌دهد. اگر یک تماس به کمپین مورد گزارش مربوط بوده و انتساب نهایی به کمپین دیگری رسیده باشد، ثبت انتساب در تاریخچهٔ هر دو قابل مشاهده است. رکوردهای هزینه در GM-04 با سطر مستقل اصلاح می‌شوند و Audit ثبت موجود حفظ می‌شود. دستور تغییر انتساب سفارش‌های قبلی وجود ندارد. جزئیات سفارش فقط به کاربر دارای `orders.read` پیوند داده می‌شود.

مدل داده و مهاجرت تازه‌ای اضافه نشده است. خواندن هزینه و تخفیف از ایندکس کمپین استفاده می‌کند. تاریخچه بر بازهٔ تاریخ سفارش و لغو محدود و ۲۵تایی صفحه‌بندی می‌شود. هزینهٔ گزارش روی حجم واقعی VPS اندازه‌گیری نشده است.

## اجرای محلی

```bash
pnpm contracts:generate && pnpm contracts:typecheck &&
pnpm api:typecheck && pnpm api:lint &&
pnpm api:test --runInBand modules/growth-attribution modules/promotions &&
pnpm admin:typecheck && pnpm admin:lint && pnpm admin:build
```

بلوک زیر از یک PostgreSQL آزمایشی با پورت آزاد استفاده می‌کند. پس از پایان اجرا، کانتینر آزمایشی متوقف می‌شود.

```bash
(
  cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" || exit 1
  cm05_db="$(docker run -d --rm \
    -e POSTGRES_USER=hamidian -e POSTGRES_PASSWORD=cm05_local \
    -e POSTGRES_DB=hamidian_cm05_test -p 127.0.0.1::5432 postgres:18.6-alpine)" || exit 1
  trap 'docker stop "$cm05_db" >/dev/null' EXIT

  for attempt in {1..30}; do
    docker exec "$cm05_db" pg_isready -q -h 127.0.0.1 \
      -U hamidian -d hamidian_cm05_test && break
    sleep 1
  done
  docker exec "$cm05_db" pg_isready -h 127.0.0.1 -U hamidian -d hamidian_cm05_test || exit 1
  cm05_address="$(docker port "$cm05_db" 5432/tcp)" || exit 1
  export DATABASE_URL="postgresql://hamidian:cm05_local@${cm05_address}/hamidian_cm05_test"

  pnpm db:generate &&
  pnpm exec prisma migrate deploy &&
  pnpm api:test:e2e --runInBand 'growth-dashboard|growth-revenue|promotion-checkout'
)
```

تست تطبیق، دو خرید قطعی، سفارشِ دارای رسید ردشده، بازپرداخت دورهٔ بعد، خرید نخست در کمپین دیگر، اصلاحیهٔ رسانه، تخفیف کالا و ارسال، تعهد سفارش پرداخت‌نشده و تفاوت تماس اول با کمپین منتخب را بررسی می‌کند. نبود دادهٔ اعتبار به‌صورت `null` آزموده می‌شود. در پنل، لینک گزارش را از داشبورد رشد و از جزئیات کمپین بررسی کنید. یک بازهٔ دارای خرید و یک بازهٔ بدون دادهٔ هزینه را باز کنید. جدول تاریخچه و پیوند اصلاحیه‌ها را بررسی کنید و با حساب بدون `finance.read` رد دسترسی گزارش را ببینید.
