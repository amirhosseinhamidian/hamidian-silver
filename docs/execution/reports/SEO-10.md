# SEO-10 — تحلیل فرصت‌ها و پیشنهادهای سئو

وضعیت `IN_REVIEW` است. پیاده‌سازی از کامیت `d2f3a2470a4f5ceed6b42fcd4041991362bf4e08` روی `seo-fix` آغاز شد. صف از دادهٔ ذخیره‌شدهٔ Search Console، خزش، پایش ایندکس، هشدارها و کاتالوگ استفاده می‌کند.

## نمونه و امتیاز

- در هر تحلیل دستی، حداکثر ۲۰۰ URL دارای نمایش کافی به‌عنوان نامزد بررسی می‌شوند. فقط Canonical فعلی محصولات، دسته‌ها، برندها و مقاله‌های منتشرشده با ۱۴ روز پوشش و حداقل ۲۰۰ نمایش Web واجد شرایط است. هشدار بحرانی فنی، noindex مشاهده‌شده، تغییر مسیر، Canonical ناسازگار یا پاسخ قطعی ۴۰۴ و ۴۱۰ نمونه را از صف خارج می‌کند. شواهد قدیمی یا ناقص در توضیح پیشنهاد مشخص‌اند.
- قواعد نسخهٔ ۱، CTR حداکثر ۱٫۸ درصد در رتبهٔ میانگین ۴ تا ۱۸، رتبهٔ ۸ تا ۱۵، افت کلیک دست‌کم ۲۵ درصد نسبت به بازهٔ قبلی، پوشش عبارت مشاهده‌شده و رابطهٔ مقالهٔ موجود با محصول یک دسته را بررسی می‌کنند. افت به هر دو بازهٔ کامل، حداقل ۲۰ کلیک و ۲۰۰ نمایش در بازهٔ پایه نیاز دارد. برای پوشش عبارت، حداقل ۵۰ نمایش در دست‌کم سه روز و هم‌پوشانی با متن توصیفی صفحه لازم است. شواهد مربوط به عبارت از جدول PAGE_QUERY می‌آیند.
- امتیاز از مجموع شدت فرصت با وزن ۳۵، حجم نمایش با وزن ۲۰، کیفیت با وزن ۲۰، اهمیت تجاری با وزن ۱۵ و موجودی با وزن ۱۰ ساخته می‌شود. حجم نمایش در ۱۲۰۰ نمایش به سقف می‌رسد. امتیاز کیفیت در بازه‌ای که سقف سطر Google را داشته باشد به ۶۵ درصد وزن کاهش می‌یابد. موجودی محصول با منطق تسویهٔ انبار پیش‌فرض و دسته با نمونهٔ حداکثر هشت محصول مستقیم آن بررسی می‌شود. موجودی نامشخص امتیاز خنثی می‌گیرد. جزئیات وزن‌ها و نسخه در پنل دیده می‌شوند.
- حداکثر ۲۰۰ پیشنهاد برتر ذخیره می‌شوند. کلید Property، Origin، موجودیت و قاعده مانع تکرار است. پیشنهادها با قالب‌های فارسی و قواعد قابل توضیح ساخته می‌شوند. اصلاح محتوا از مسیر ویرایش موجود محصول، دسته یا مقاله انجام می‌شود.

## تصمیم و سنجش

در «عملکرد جست‌وجو ← فرصت‌های سئو» می‌توان دلیل، پیشنهاد، متریک، محدودیت و لینک گزارش را دید. تأیید، رد، تعویق یا تبدیل به تسک اصلاحی با تاریخچهٔ کاربر ذخیره می‌شود. تحلیل بعدی می‌تواند موردِ هنوز معتبر را پس از پایان تعویق به صف برگرداند. پیش از تأیید یا ساخت تسک، انتشار و Canonical فعلی دوباره بررسی می‌شوند. نمایش به `settings.read` و تحلیل، تصمیم و ثبت اجرا به `settings.write` نیاز دارند.

تسک، دستور پیشنهادی و URL را نگه می‌دارد. مدیر تاریخ اجرا، تغییر انجام‌شده، عوامل مداخله‌گر و بازهٔ ۷، ۱۴ یا ۲۸روزه را ثبت می‌کند. گزارش از سطح PAGE همان URL در دو بازهٔ برابر پیش و پس از اجرا به دست می‌آید و روز اجرا کنار گذاشته می‌شود. وقتی دادهٔ کامل برای هر دو بازه موجود باشد، اختلاف کلیک، نمایش و CTR ثبت می‌شود. گزارش مشاهده‌ای برای بازبینی انسانی است. تاریخچهٔ گزارش با نسخهٔ بعدی حفظ می‌شود.

## بررسی محلی

از ریشهٔ پروژه اجرا کنید.

```bash
cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" &&
pnpm contracts:generate &&
pnpm api:lint &&
pnpm api:typecheck &&
pnpm api:test --runInBand modules/seo modules/authorization &&
pnpm admin:lint &&

```

بلوک زیر مهاجرت، امتیازدهی، جلوگیری از تکرار، گردش تصمیم، ثبت تسک و دو پنجرهٔ مقایسه را با PostgreSQL موقت بررسی می‌کند.

```bash
(
  cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" || exit 1
  seo10_db="$(docker run -d --rm \
    -e POSTGRES_USER=hamidian -e POSTGRES_PASSWORD=seo10_e2e_local \
    -e POSTGRES_DB=hamidian_seo10_test -p 127.0.0.1::5432 postgres:18.6-alpine)" || exit 1
  trap 'docker stop "$seo10_db" >/dev/null 2>&1' EXIT
  for attempt in {1..30}; do
    docker exec "$seo10_db" pg_isready -q -h 127.0.0.1 -U hamidian -d hamidian_seo10_test && break
    sleep 1
  done
  docker exec "$seo10_db" pg_isready -h 127.0.0.1 -U hamidian -d hamidian_seo10_test || exit 1
  seo10_address="$(docker port "$seo10_db" 5432/tcp)" || exit 1
  case "$seo10_address" in 127.0.0.1:[0-9]*) ;; *) exit 1 ;; esac
  export DATABASE_URL="postgresql://hamidian:seo10_e2e_local@${seo10_address}/hamidian_seo10_test?schema=public"

  pnpm db:generate &&
  pnpm exec prisma migrate deploy &&
  pnpm api:test:e2e --runInBand 'seo-opportunities|seo-issue-workflow'
)
```

برای بازبینی پنل می‌توان از دیتابیس محلی دارای تاریخچهٔ هماهنگ با همان Property و Origin استفاده کرد. در صف فرصت‌ها «تحلیل داده‌های ثبت‌شده» را اجرا و از جزئیات پیشنهاد، دلیل و امتیاز را بررسی کنید. سپس روی یک مورد آزمایشی تصمیم ثبت کنید، تسک بسازید و تاریخ اجرا و عوامل مداخله‌گر را ثبت کنید. وضعیت دادهٔ ناکافی و گزارش پیش‌وپس در آزمون PostgreSQL پوشش داده شده‌اند.
