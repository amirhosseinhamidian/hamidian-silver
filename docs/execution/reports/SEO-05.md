## نمای عملکرد

در پنل، مسیر «مدیریت سامانه ← عملکرد جست‌وجو» چهار شاخص کلیک، نمایش، نرخ کلیک و رتبهٔ متوسط را نشان می‌دهد. تاریخ انتخابی روز میلادیِ Search Console در منطقهٔ زمانی اقیانوس آرام است. بازهٔ پیش‌فرض ۲۸ روز است و سه روز پیش از روز جاری پایان می‌یابد. دو سر بازه شامل‌اند و حداکثر طول ۹۰ روز است. دورهٔ قبلی هم‌طول است و روز قبل از شروع دورهٔ جاری پایان می‌یابد. [مبنای روز در API گوگل](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)

برای هر روز و نوع جست‌وجو، نسخهٔ روز زمان‌بندی‌شده از آخرین اجرای موفق انتخاب می‌شود. نمایش یک روز فقط به ردیف‌های مشاهده‌شده در همان اجرا تکیه دارد. تاریخچهٔ ردیف‌های مشاهده‌نشده در پایگاه داده حفظ می‌شود. روزِ همگام‌شدهٔ بدون ردیف و روزِ همگام‌نشده پوشش جدا دارند. مقدار گزارش‌شدهٔ صفر معتبر است. نبود مقدار با خط تیره مشخص می‌شود. اگر هر روز از یکی از دو بازه داده نداشته باشد، بخش تغییر خالی می‌ماند و تعداد روزهای دارای داده برای هر دو بازه نمایش داده می‌شود.

نرخ کلیک از مجموع کلیک تقسیم بر مجموع نمایش محاسبه می‌شود. رتبه با تعداد نمایش وزن می‌گیرد و اگر بخشی از نمایش‌ها رتبه نداشته باشند، مقدار رتبه خالی است. تغییر نرخ کلیک در واحد درصد و تغییر رتبه در واحد جایگاه نشان داده می‌شود. نمودار روزانه و گروه‌های هفت‌روزهٔ آغازشده از ابتدای بازه، جدول قابل خواندن با صفحه‌کلید دارند. گروه ناقص در نمودار نشانهٔ جدا دارد.

## فیلتر و جدول‌ها

| نما        | منبع ذخیره‌شده                                                              |
| ---------- | --------------------------------------------------------------------------- |
| نمای کلی   | `PROPERTY` برای مجموع سایت، `DEVICE` برای دستگاه                            |
| تفکیک برند | `BRAND` با منبع `google`، فقط برای Web و بدون فیلتر دستگاه                  |
| جدول عبارت | `QUERY` و تجمیع در سطح Property، در نمای بدون فیلتر دستگاه و برند           |
| جدول صفحه  | `PAGE` در نمای پایه و `PAGE_DEVICE` در نمای دستگاه، با URL گزارش‌شدهٔ مستقل |

نوع‌های ذخیره‌شده Web، Image، Video و News هستند. فیلتر دستگاه یا برند در جدول‌هایی که مجموعهٔ ابعاد متناظر ندارند پیام روشن دارد. برای جست‌وجوی جدول، تطبیق زیررشته بدون حساسیت به بزرگی حروف است. ترتیب براساس کلیک، نمایش، نرخ، رتبه یا نام با نام به‌عنوان کلید نهایی پایدار است. هر صفحه پیش‌فرض ۲۵ و حداکثر ۵۰ ردیف دارد. تعداد روزهای رسیده به سقف دریافت در جدول ثبت می‌شود. گوگل عبارت‌های ناشناس‌شده را از جدول حذف می‌کند و ممکن است فقط ردیف‌های برتر را بدهد. مجموع در سطح صفحه نیز با مجموع Property تفاوت دارد. [محدودیت گزارش Search Console](https://developers.google.com/search/blog/2022/10/performance-data-deep-dive?hl=en)

## امنیت و اجرا

صفحه و هر دو مسیر API به `settings.read` احتیاج دارند. داشبورد فقط Property تنظیم‌شده را می‌خواند. Cache پاسخ خصوصی و مسدود است و API از Cache فرایندی ۳۰ثانیه‌ای با سقف ۴۸ کلید برای هر گزارش استفاده می‌کند. پرس‌وجوی جدول به‌صورت گروه‌بندی و صفحه‌بندی PostgreSQL انجام می‌شود و هم‌زمانی آن چهار درخواست در هر فرایند است. زمان آخرین Sync موفق، توقف صف و خطاهای شناخته‌شده از تاریخچه نشان داده می‌شوند. ORM و SQL از جداول و شاخص‌های SEO-04 استفاده می‌کنند. این تسک Migration تازه ندارد. تست پذیرش با دادهٔ آزمایشی انجام می‌شود و به کلید Google نیاز ندارد.

## اجرای دستی

```bash
pnpm contracts:generate && pnpm contracts:typecheck &&
pnpm api:lint && pnpm api:typecheck &&
pnpm api:test --runInBand modules/seo &&
pnpm admin:lint && pnpm admin:typecheck &&
pnpm admin:test --shard=1/2 && pnpm admin:test --shard=2/2 &&
pnpm admin:build
```

پس از تنظیم `SEO05_TEST_DATABASE_URL` روی PostgreSQL مجزای آزمایشی، مهاجرت‌های موجود و تست HTTP را اجرا کنید. [راهنمای راه‌اندازی دیتابیس آزمایشی](SEO-04.md#بررسی-دستی)

```bash
DATABASE_URL="${SEO05_TEST_DATABASE_URL:?}" pnpm exec prisma migrate deploy &&
DATABASE_URL="${SEO05_TEST_DATABASE_URL:?}" pnpm api:test:e2e --runInBand search-overview
```

تست HTTP با دادهٔ واقعی PostgreSQL پاسخ‌های ۴۰۱ و ۴۰۳، اختلاف دوره‌های هم‌طول، CTR و رتبهٔ وزن‌دار، نبود داده، خطای Sync، تفکیک گوگل و برآورد، ردیف قدیمی، جست‌وجوی متنی، ترتیب پایدار و صفحه‌بندی را کنترل می‌کند. برای بازبینی پنل، با کاربر دارای `settings.read` یک بازه را باز کنید، نمودار روزانه را به هفتگی عوض کنید و در بخش صفحه‌ها دستگاه و ترتیب را تغییر دهید.

مدیر پروژه موفقیت تست‌های محلی را پس از رفع خطای `react-hooks/purity` تأیید کرد. تشخیص توقف فعال همگام‌سازی در مرحلهٔ دریافت داده انجام می‌شود. نتیجهٔ آزمون PostgreSQL و بازبینی دستی پنل در انتظار ثبت است.
