## رفتار فروشگاه

- فهرست اصلی محصولات و صفحات دسته و برند از پاسخ فهرست و Facetهای PD-01 استفاده می‌کنند. دامنهٔ ثابت دسته و برند از مسیر صفحه می‌آید. لینک‌های قبلی کشور با افزودن `scopeCountry` به API Facet همچنان قابل ترکیب با فیلترهای دیگر هستند.
- نوار کنار فهرست در دسکتاپ و پنل Radix در موبایل از یک فرم استفاده می‌کنند. دسته، برند، سایز و ویژگی‌ها چندانتخابی‌اند و هر گزینه تعداد محصول خود را نشان می‌دهد. ورود بازهٔ قیمت، وزن، طول و ویژگی عددی ارقام فارسی، عربی و لاتین را می‌پذیرد. حذف یک انتخاب، پاک‌کردن همه و مرتب‌سازی از کنترل‌های مستقل انجام می‌شوند.
- فیلترها و ترتیب در Query String ذخیره می‌شوند و Back/Forward همان فهرست را بازیابی می‌کند. اعمال فیلتر یا تغییر ترتیب به صفحهٔ اول می‌رود. پاک‌کردن فیلترها ترتیب فعلی و مسیر مجموعه را حفظ می‌کند. نمایش بیشتر و لینک صفحهٔ بعد فیلترها را همراه دارند.
- شمارش از پاسخ API می‌آید. در زمان ناوبری وضعیت بارگذاری اعلام می‌شود و درخواست‌های قدیمیِ صفحه‌بندی با AbortSignal لغو یا کنار گذاشته می‌شوند. Back/Forward و تغییر مسیر از App Router استفاده می‌کنند. [رفتار انتقال‌های App Router](https://nextjs.org/docs/app/api-reference/file-conventions/loading)
- نتیجهٔ خالی، فیلتر منقضی‌شده، صفحهٔ خارج از بازه و نمایش محصول ناموجود پیام یا مسیر اقدام جداگانه دارند. محصول ناموجود برچسب و لینک مشاهده دارد. پنل موبایل با Escape بسته می‌شود و تمرکز به دکمهٔ بازکردن برمی‌گردد.

## اثر روی SEO

مسیرهای HTML و لینک محصولات، زنجیرهٔ Redirect دسته، Sitemap و JSON-LD قبلی حفظ شده‌اند. Query String فیلتر و Sort تحت سیاست موجود در SSR با `noindex` و Canonical مسیر پایه پاسخ می‌گیرد. شمار صفحه برای صفحه‌بندی بدون فیلتر به Canonical اضافه می‌شود و 404 صفحات تمیزِ خارج از بازه برقرار است. پنل از دکمه و فرم استفاده می‌کند و فهرست پیوندهای قابل خزش برای ترکیب Facetها تولید نمی‌کند. مسیر داخلی صفحه‌بندی API هم `X-Robots-Tag: noindex, nofollow` دارد.

## اجرای دستی

از ریشهٔ پروژه، تولید قرارداد و بررسی‌های API و Storefront را اجرا کنید:

```bash
pnpm contracts:generate &&
pnpm contracts:typecheck &&
pnpm api:lint &&
pnpm api:typecheck &&
pnpm storefront:lint &&
pnpm storefront:typecheck &&
pnpm storefront:test
```

برای بررسی کشور در PostgreSQL، با دیتابیس آزمایشی دارای مهاجرت‌ها اجرا کنید:

```bash
DATABASE_URL="$PD01_TEST_DATABASE_URL" pnpm api:test:e2e --runInBand catalog-facets
```

پورت‌های ۴۳۱۰ و ۴۳۱۱ باید برای Storefront و Mock API این اجرای Playwright در دسترس باشند. تست جدید روی پروفایل‌های دسکتاپ، تبلت و موبایل اجرا می‌شود:

```bash
pnpm storefront:test:e2e catalog-facets.spec.ts
```

تست‌ها ترکیب فیلتر، شمارش، مرتب‌سازی، Back/Forward، پاک‌کردن فیلتر، تمرکز پنل، حالت خالی و ناموجودی را می‌سنجند. تست واحد درخواست صفحه‌بندی لغوشده و دریافت پاسخ دیررس را پوشش می‌دهد.

در اجرای دستی مرورگر، ۳۷ تست موفق، ۲ تست Skip و ۶ تست ناموفق بود. شکست‌ها در هر سه پروفایل برای نام گزینهٔ انتخاب‌شده با شمارش صفر و صفحهٔ دوم نمونهٔ برند تکرار شدند. بازیابی برچسب گزینه‌های انتخاب‌شده اضافه شد و Mock برند نمونه دو صفحه را برای آزمون SEO برگرداند.

در اجرای متمرکز بعدی، ۲۰ تست موفق و یک تست دسکتاپ ناموفق بود. صفحه نمونهٔ برند و Canonical در هر سه پروفایل موفق بودند. Trace دسکتاپ نشان داد برچسب `atelier` در همان ناوبری ظاهر شد که فهرست برند در کش ۶۰ ثانیه‌ای تازه شد. بازیابی برچسب‌های غایب اکنون فهرست عمومی را همان لحظه با `no-store` می‌خواند. مدیر پروژه موفقیت تست واحد و اجرای مجدد هر دو فایل Playwright زیر را تأیید کرد. [رفتار کش fetch در Next.js](https://nextjs.org/docs/app/api-reference/functions/fetch#optionscache)
