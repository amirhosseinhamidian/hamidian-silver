# PD-04 — مرتب‌سازی تجاری و محصولات منتخب

وضعیت `IN_REVIEW` است. پیاده‌سازی از `775e5d1` روی `seo-fix` شروع شد و کامیت `b0938b49bc3a43f22db30a9957bf24ee7a316dc5` روی همان شاخه تأیید شد. اجرای E2E PostgreSQL و بررسی Query Plan در PD-01 همچنان در انتظار ثبت است.

## ترتیب نسخهٔ ۱

ابتدا دامنهٔ دسته، برند یا کشور، نتایج جست‌وجو، سایر فیلترها و شرایط انتشار اعمال می‌شوند. گزینه‌های `availability`، `best-selling` و `featured` به فهرست عمومی و API فیلترها اضافه شده‌اند. API در این سه حالت نسخه، ترتیب درخواستی و ترتیب اعمال‌شده را برمی‌گرداند. فهرست‌های دسته و برند در فروشگاه از همان قرارداد Facet استفاده می‌کنند. فهرست کمپین نیز می‌تواند از همین قرارداد استفاده کند.

| ترتیب                          | قاعده                                                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| جدیدترین، قیمت کم یا زیاد، نام | ترتیب قبلی هر endpoint حفظ شده است.                                                                                |
| بیشترین موجودی                 | پس از اولویت محصولات موجود، تعداد قابل‌خرید از زیاد به کم، سپس امتیاز جست‌وجو، زمان ایجاد و شناسه.                 |
| پرفروش‌ها                      | پس از اولویت محصولات موجود، تعداد سفارش متمایز و واجد شرایط از زیاد به کم، سپس امتیاز جست‌وجو، زمان ایجاد و شناسه. |
| اولویت فروشگاه                 | پس از اولویت محصولات موجود، ابتدا سنجاق، سپس وزن بیشتر، امتیاز جست‌وجو، زمان ایجاد و شناسه.                        |

هر محصول برای ورود به رتبه‌بندی فروش به دست‌کم ۳ سفارش پرداخت‌شده در ۳۰ روز گذشته نیاز دارد. سفارش باید در وضعیت پرداخت‌شده، در حال پردازش، ارسال‌شده یا تحویل‌شده باشد. پرداخت باید تأییدشده باشد یا بخشی از آن استرداد شده باشد. فقط ردیف‌هایی که تعداد خرید آن‌ها بعد از مرجوعی مثبت است شمارش می‌شوند. چند ردیف از یک محصول در یک سفارش یک‌بار شمرده می‌شوند. اگر هیچ محصولی در نتیجهٔ فیلتر به حداقل نرسد، ترتیب جدیدترین اعمال می‌شود و فروشگاه دلیل را نمایش می‌دهد. تعداد سفارش از API عمومی خارج نمی‌شود.

شناسهٔ یکتا در انتهای ترتیب، مرز صفحات را برای دادهٔ یکسان تعیین می‌کند. تغییر فیلتر، موجودی، وضعیت سفارش یا زمان انقضای اولویت میان دو درخواست می‌تواند جای محصول را عوض کند. محاسبهٔ سفارش فقط در حالت `best-selling` انجام می‌شود و از شاخص زمان پرداخت و کلیدهای اتصال سفارش استفاده می‌کند. هزینهٔ Query با حجم واقعی داده هنوز اندازه‌گیری نشده است.

## اولویت‌گذاری در پنل

در صفحهٔ ویرایش محصول، برای محصول منتشرشده می‌توان سنجاق یا وزن ۱ تا ۱۰۰ را با بازه‌ای حداکثر ۹۰روزه فعال کرد. شروع شامل بازه و پایان خارج از بازه است. تاریخ‌ها در فرم به وقت تهران و در API به شکل تاریخ مطلق‌اند. سقف ۲۴ شامل اولویت‌های فعال و زمان‌بندی‌شده است. اولویت منقضی یا غیرفعال ظرفیت مصرف نمی‌کند. تنظیم برای هر محصول مستقل از قیمت و موجودی نگه‌داری می‌شود.

ویرایش با نسخهٔ مورد انتظار در تراکنش Serializable انجام می‌شود. نسخهٔ قدیمی و محدودیت ظرفیت پاسخ ۴۰۹ دارند. تنظیمات از مجوز کاتالوگ و ثبت رویداد ویرایش Audit استفاده می‌کنند. مهاجرت یک جدول مستقل با قید بازه و وزن اضافه می‌کند. فهرست منتخب صفحهٔ اصلی مسیر تنظیمات خودش را دارد.

## اثر بر SEO

مرتب‌سازی تعاملی در پارامتر `sort` ثبت می‌شود و از سیاست فعلی Canonical صفحهٔ پایه و `noindex` پیروی می‌کند. لینک صفحه‌بندی دامنه و ترتیب انتخاب‌شده را حفظ می‌کند. URL صفحات محصولات و دسته‌ها، لینک HTML مقصد، پاسخ‌های Redirect و 404، عضویت Sitemap و نوع JSON-LD از قواعد فعلی استفاده می‌کنند. Playwright بازگشت به ترتیب جدیدترین و Canonical دسته را بررسی می‌کند.

## اجرای دستی

```bash
pnpm db:generate &&
pnpm contracts:generate && pnpm contracts:typecheck &&
pnpm api:lint && pnpm api:typecheck && pnpm api:test --runInBand modules/catalog &&
pnpm frontend:lint && pnpm frontend:typecheck && pnpm frontend:test &&
pnpm storefront:test:e2e catalog-facets.spec.ts
```

پس از تنظیم `PD04_TEST_DATABASE_URL` برای پایگاه مجزای آزمایشی، مهاجرت و E2E را اجرا کنید. [روش انتخاب پورت آزاد و راه‌اندازی PostgreSQL آزمایشی](SEO-04.md#بررسی-دستی)

```bash
DATABASE_URL="${PD04_TEST_DATABASE_URL:?}" pnpm exec prisma migrate deploy &&
DATABASE_URL="${PD04_TEST_DATABASE_URL:?}" pnpm api:test:e2e --runInBand 'catalog-(ranking|facets)'
```

سناریوی پایگاه داده، سفارش‌های معتبر و نامعتبر، حداقل فروش، فیلتر قیمت، ثبات صفحات، ترتیب موجودی، زمان‌بندی، سقف ۲۴، نسخهٔ قدیمی و حفظ قیمت و موجودی را می‌سنجد. بازبینی دستی پنل شامل فعال‌سازی، غیرفعال‌سازی، نمایش زمان تهران و اطمینان از اعمال ترتیب در فروشگاه است.

مدیر پروژه اجرای موفق هر دو بخش Vitest پنل (`--shard=1/2` و `--shard=2/2`) و Playwright فهرست را تأیید کرد. در اجرای اولیه، ۳۶۰ تست پنل پاس شدند و Vitest به‌دلیل timeout ارتباط worker با کد ۱ خارج شد. نتیجهٔ مهاجرت و E2E روی PostgreSQL و بازبینی دستی فرم پنل در انتظار ثبت است.
