# CX-03 — پیشنهاد مکمل و بسته‌های ترکیبی

وضعیت `IN_REVIEW` روی `seo-fix` است. پیش‌نیازهای `CAT-03`، `CM-02` و `GM-01` در ردیاب پذیرفته شده‌اند. این مرحله پس از تصمیم مدیر پروژه برای ادامهٔ رودمپ پیش از انتشار آغاز شد.

## رفتار

- مدیر در فرم محصول و بخش «محصولات مرتبط» می‌تواند هر رابطهٔ دوطرفه را تعیین یا حذف کند. روابط دستیِ قابل خرید اولویت دارند. پیشنهاد خودکار از دسته‌های فعال مشترک می‌آید و با ویژگی‌های ثبت‌شدهٔ مشترک، سایز قابل خرید مشترک و فاصلهٔ قیمت مرتب می‌شود. فقط واریانت قیمت‌دار و قابل رزرو در انبار پیش‌فرض برای ورود پیشنهاد کافی است.
- پیشنهادها از مسیر عمومی محصولات مرتبط در جزئیات کالا، سبد و لندینگ فعال خوانده می‌شوند. در سبد و لندینگ حداکثر چهار کارت نمایش داده می‌شود. سبد حداکثر سه محصول مبنا دارد و لندینگ از اولین محصول نتایج همان صفحه شروع می‌کند. محصول داخل سبد یا فهرست فعلی لندینگ کنار گذاشته می‌شود. خطای دریافت پیشنهاد، خرید و نمایش صفحه را متوقف نمی‌کند.
- نمایش کارت پس از ورود به محدودهٔ دید و انتخاب آن با ابزار Measurement فعلی و برچسب جدا برای سه جایگاه ثبت می‌شوند. باز و بسته شدن بخش دید روی همان کارت در همان نمونهٔ صفحه نمایش تکراری ثبت نمی‌کند. ارسال از سازوکار رضایت و حذف تکرار فعلی استفاده می‌کند.
- بستهٔ ثابتِ کاتالوگ یک واریانت ترکیبی با اجزای مشخص است. Checkout همهٔ اجزای آن را در یک تراکنش رزرو می‌کند. در پیشنهاد ترکیبی کمپین، اقلام مستقل در سبد قابل حذف‌اند. حذف یک قلم لازم، Quote قبلی را نامعتبر می‌کند و تخفیف فقط برای بستهٔ کامل محاسبه می‌شود. قیمت نهایی هر دو حالت از موتور موجود خوانده می‌شود.

## SEO و پذیرش

پیوند HTML کارت‌ها به مسیر فعلی محصول می‌رود و پاسخ JSON پیشنهادها `X-Robots-Tag: noindex` دارد. URL عمومی، وضعیت HTTP صفحات، Redirect، Canonical، Robots صفحات، Sitemap و JSON-LD تغییر نکرده‌اند.

- آزمون PostgreSQL روابط دستی، رتبهٔ خودکار، صفحه‌بندی و حذف محصول موجود فقط در انبار فرعی را می‌پوشاند. تست پرداخت، تغییر Quote بعد از حذف قلم، عدم ثبت سفارش در کسری موجودی و رزرو هر دو جزء بسته را بررسی می‌کند.
- تست فروشگاه حذف کارت‌های تکراری و ناموجود و یک‌بار ثبت نمایش و کلیک را پوشش می‌دهد. پذیرش عملی سه جایگاه در موبایل و دسکتاپ باز است.
- خطای TypeScript در دادهٔ ساختگی `IntersectionObserverEntry` برطرف شد. نتیجهٔ اجرای مجدد Type Check در انتظار گزارش است.
- از ۳۳ آزمون مرورگر در اجرای اول، ۳۱ مورد پاس شدند. در Tablet و Mobile، ردگیری ناوبری وجود هم‌زمان Canonical و Robots دستهٔ مادر و زیردسته را بلافاصله پس از کلیک ثبت کرد. تست اکنون منتظر یکتا شدن هر دو تگ می‌ماند و یکتایی Canonical را در پاسخ مستقیم HTML هم می‌سنجد. مدیر پروژه پس از اصلاح، موفقیت اجرای مجدد را گزارش کرد.
- سه مجموعهٔ API E2E در اجرای اولیهٔ مدیر پروژه به‌دلیل نبود `DATABASE_URL` هنگام ساخت Prisma متوقف شدند. نتیجهٔ سناریوها در انتظار اجرای بلوک کامل PostgreSQL است.

بلوک زیر در همان اجرای ترمینال، کانتینر موقت PostgreSQL را با پورت آزاد آماده می‌کند، `DATABASE_URL` را تنظیم می‌کند و پس از مهاجرت هر سه مجموعه را اجرا می‌کند. نتیجهٔ `catalog-facets` شاهد PostgreSQL بازِ `PD-02` برای شروع `CX-04` است.

```bash
(
  cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" || exit 1
  cx03_db="$(docker run -d --rm \
    -e POSTGRES_USER=hamidian -e POSTGRES_PASSWORD=cx03_e2e_local \
    -e POSTGRES_DB=hamidian_cx03_test \
    -p 127.0.0.1::5432 postgres:18.6-alpine)" || exit 1
  trap 'docker stop "$cx03_db" >/dev/null 2>&1' EXIT

  for attempt in {1..30}; do
    docker exec "$cx03_db" pg_isready -q -h 127.0.0.1 -U hamidian -d hamidian_cx03_test && break
    sleep 1
  done
  docker exec "$cx03_db" pg_isready -h 127.0.0.1 -U hamidian -d hamidian_cx03_test || exit 1
  cx03_address="$(docker port "$cx03_db" 5432/tcp)" || exit 1
  case "$cx03_address" in 127.0.0.1:[0-9]*) ;; *) exit 1 ;; esac
  export DATABASE_URL="postgresql://hamidian:cx03_e2e_local@${cx03_address}/hamidian_cx03_test?schema=public"

  pnpm db:generate &&
  pnpm exec prisma migrate deploy &&
  pnpm api:test:e2e --runInBand 'catalog-attributes|promotion-checkout|catalog-facets'
)
```
