## دفتر و مانده

هر بستهٔ اعتبار به حساب، سفارش مبنا، نوع پاداش خرید یا معرفی، شناسهٔ منبع، نسخهٔ مؤثر سیاست و سررسید UTC متصل است. برای هر سفارش پرداخت‌شده حداکثر یک بستهٔ پاداش خرید ثبت می‌شود. منبع در هر نوع یکتاست. دفتر برای صدور، فعال‌سازی، رزرو، آزادسازی، مصرف، انقضا و برگشت، مبلغ صحیح تومان و وضعیت مبدا و مقصد را ثبت می‌کند. PostgreSQL تغییر، حذف یا خالی کردن مستقیم جدول رخدادهای دفتر را رد می‌کند. هر رخداد و تغییر Snapshot همان بسته در یک تراکنش ثبت می‌شود. قید پایگاه داده جمع وضعیت‌های هر بسته را برابر مبلغ صادرشده نگه می‌دارد.

رزرو بسته‌های قابل مصرف را از نزدیک‌ترین انقضا انتخاب می‌کند و در سررسید برابر از شناسهٔ بسته برای ترتیب پایدار استفاده می‌کند. قفل تراکنشی به‌ازای حساب از رزرو یا تغییر هم‌زمان یک مانده جلوگیری می‌کند. شاخص یکتا یک رزرو باز یا مصرف قطعی برای هر سفارش نگه می‌دارد. پس از آزادسازی، همان سفارش می‌تواند رزرو تازه داشته باشد. تکرار کلید و ورودی همسان همان حرکت‌های ثبت‌شده را برمی‌گرداند. استفاده از همان کلید با ورودی متفاوت رد می‌شود. اتصال بعدی Checkout می‌تواند تراکنش خود را به عملیات بدهد و باید خطای عملیات را به همان تراکنش منتقل کند تا هر دو تغییر با هم برگشت بخورند.

ماندهٔ قابل استفاده و در انتظار فعال‌سازی به سررسید بسته محدود است. ماندهٔ رزروشده پس از سررسید هم تا دریافت نتیجه باقی می‌ماند. انقضا فقط سهم آزاد یا در انتظار را جابه‌جا می‌کند. آزادسازی یا برگشت مصرف، مبلغ را به همان بسته و مهلت اصلی برمی‌گرداند. اگر مهلت گذشته باشد، مقصد وضعیت منقضی است. برگشت مصرف در سطح همان رزرو و بسته از مبلغ مصرف‌شدهٔ باقی‌مانده بیشتر نمی‌شود. ابطال تخصیص فقط از اعتبار خرج‌نشده یا در انتظار همان بسته کم می‌کند. کار زمان‌بندی‌شدهٔ انقضا و تطبیق وضعیت پرداخت در WL-05 است.

## مسیرهای API

| مسیر | دسترسی و کارکرد |
| --- | --- |
| `GET /api/v1/wallet` | حساب واردشده، ماندهٔ خودش در انتظار، قابل استفاده، رزروشده و نزدیک‌ترین سررسید قابل مصرف را می‌بیند. |
| `GET /api/v1/wallet/admin/{userId}` | `finance.read`، ماندهٔ حساب |
| `GET /api/v1/wallet/admin/{userId}/ledger` | `finance.read`، دفتر صفحه‌بندی‌شده با منبع، سفارش و نسخهٔ سیاست |
| `POST /api/v1/wallet/admin/{userId}/corrections` | `finance.read` و `finance.write`، ابطال اعتبار خرج‌نشده یا برگشت مصرفِ رزرو قبلی |

اصلاح دستی شناسهٔ درخواست، مبلغ، دلیل و شناسهٔ اقدام‌کننده را ثبت می‌کند. مسیر عمومی مانده فقط از شناسهٔ Principal استفاده می‌کند. اتصال رزرو به پرداخت، صدور خودکار و رابط نمایش کیف پول در مراحل بعد انجام می‌شوند. مهاجرت افزایشی است و برای حساب‌های موجود اعتباری ایجاد نمی‌کند.

## اجرای محلی

```bash
pnpm contracts:generate && pnpm contracts:typecheck &&
pnpm db:validate && pnpm api:lint && pnpm api:typecheck &&
pnpm api:test --runInBand modules/wallet modules/reward-policies modules/audit
```

برای E2E یک پایگاه دادهٔ آزمایشی تازه بسازید. دادهٔ آزمون عمداً از دفتر تغییرناپذیر پاک نمی‌شود. بلوک زیر از پورت آزاد محلی استفاده می‌کند و در پایان کانتینر را متوقف می‌کند.

```bash
(
  cd "/Users/amirhosseinhamidian/Projects/hamidian-silver" || exit 1
  wl02_db="$(docker run -d --rm \
    -e POSTGRES_USER=hamidian -e POSTGRES_PASSWORD=wl02_local \
    -e POSTGRES_DB=hamidian_wl02_test -p 127.0.0.1::5432 postgres:18.6-alpine)" || exit 1
  trap 'docker stop "$wl02_db" >/dev/null' EXIT

  for attempt in {1..30}; do
    docker exec "$wl02_db" pg_isready -q -h 127.0.0.1 \
      -U hamidian -d hamidian_wl02_test && break
    sleep 1
  done
  docker exec "$wl02_db" pg_isready -h 127.0.0.1 -U hamidian -d hamidian_wl02_test || exit 1
  wl02_address="$(docker port "$wl02_db" 5432/tcp)" || exit 1
  export DATABASE_URL="postgresql://hamidian:wl02_local@${wl02_address}/hamidian_wl02_test"

  pnpm db:generate &&
  pnpm exec prisma migrate deploy &&
  pnpm api:test:e2e --runInBand 'wallet-ledger|reward-policies'
)
```

آزمون PostgreSQL دو سفارش با درخواست رزرو ۷۵۰۰ تومان روی ماندهٔ ۱۰ هزار تومان ایجاد می‌کند. انتظار می‌رود تنها یکی موفق شود و ۲۵۰۰ تومان قابل مصرف بماند. سپس تکرار درخواست، برگشت تراکنش میزبان، برداشت از بستهٔ نزدیک‌تر به انقضا، برگشت جزئی مصرف، محدودیت دسترسی و دلیل اصلاح، انقضا، منع تغییر دفتر و تطبیق جمع دفتر با Snapshot سنجیده می‌شوند.
