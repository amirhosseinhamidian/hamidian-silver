# برنامه اجرایی یکپارچه گالری حمیدیان

دو مرجع اجرایی پروژه [SEO Intelligence v2](SEO_ROADMAP.md) با ۱۰ تسک در ۵ فاز و [Product Discovery & Campaign Growth](GROWTH_ROADMAP.md) با ۳۷ تسک در ۸ فاز هستند. شناسه‌ها و معیارهای پذیرش از متن مرجع آمده‌اند. مراحل A تا I ترتیب پیشنهادی تحویل‌اند و گراف پیش‌نیازها ملاک آماده بودن تسک است.

## خط مبنای مخزن

- شاخه رسمی `main` در کامیت `e0d268d3004a013ba49d0fc3000e5e96fa0181ad` با `origin/main` همگام شد. درخت کاری پیش از مستندسازی تمیز بود. در این خط مبنا فایل AGENTS در ریشه یا زیرمسیرها و پوشه `docs/execution` وجود نداشت.
- ریشه، workspace هشت‌پکیجی pnpm `11.9.0` با Node `24.9.0` است. دو برنامه وب Next `16.3.3`، React `19.2.8` و Tailwind `4` دارند. API از NestJS `12`، TypeScript `5.9.3` و Prisma `7.10.0` استفاده می‌کند. Compose شامل PostgreSQL `18.6` و Redis `8.10.0` است. Telegram relay برنامه چهارم است.
- مسیرها و فرمان‌های تأییدشده در [AGENTS.md](../../AGENTS.md) آمده‌اند. [CI](../../.github/workflows/production.yml) برای PR به main و push شاخه‌های تعریف‌شده، نصب frozen، تولید قرارداد، Prisma validate/migrate روی PostgreSQL CI، verify، تست‌های استقرار و Playwright را اجرا می‌کند. Deploy روی push به main مشروط به تنظیم انتشار است.
- [ممیزی قبلی SEO](../seo-production-audit.md)، [راهنمای انتشار دانستنی](../seo-guide-release-runbook.fa.md)، [تست خرید](../storefront-purchase-e2e.md)، مستندات VPS، Admin، درگاه و کاوه‌نگار شواهد قابل استفاده‌اند. وجود مستندات یا کد به‌تنهایی پذیرش تسک جدید را ثابت نمی‌کند.

## زیرساخت مشترک و گیت‌ها

- **کاتالوگ و SEO**. `Category.parentId`، اتصال چنددسته‌ای محصول، `ProductAttribute`، واریانت و موجودی، API عمومی و فرم ادمین موجودند. CAT-01 باید شکاف دسته/ویژگی/واریانت را قبل از هر Migration ثبت کند. حفظ URL، Breadcrumb، Canonical و Sitemap برای CAT و PD و صفحه فرود CM مشترک است. PD-05 پس از PD-01/02 و کنترل سخت‌گیرانه هر دو گیت SEO-01 و SEO-02 برنامه‌ریزی شده است. برای انتشار قابلیت فیلتر از گیت PD-05 عبور شود.
- **جست‌وجو و سنجش**. API فهرست، پیشنهاد جست‌وجو و کد GA4 موجودند. قابلیت شمارش Facet با موجودی واقعی، قرارداد رویداد سروری و Attribution در گیت‌های PD و GM جداگانه اعتبارسنجی می‌شوند. Smart Collections و Gift Finder از قرارداد مشترک انتخاب محصول استفاده می‌کنند. پیش از تثبیت UTM، رفتار Noindex روی URLهای دارای پارامتر با SEO بررسی شود.
- **سفارش و پرداخت**. بازاستفاده از مدل‌های Order/PaymentAttempt، مسیرهای درگاه فعلی و تأیید کارت‌به‌کارت، Pricing و Snapshot سفارش بررسی شود. GM-03 منبع درآمد تأییدشده و CM-02 قرارداد تخفیف را تثبیت می‌کنند. کیف پول و Referral روی همان مسیرهای قطعی پرداخت و بازگشت اعتبار طراحی می‌شوند.
- **زیرساخت سئو و Job**. ماژول SEO فعلی به Redirect و Sitemap عمومی سرویس می‌دهد. `ScheduleModule`، Outbox اعلان و تلگرام موجودند. در خط مبنای بررسی‌شده برای Search Console Sync، UrlInventory، Ledger و Referral معادل آمادهٔ پذیرش شناسایی نشد. پیش از افزودن Worker یا صف، تناسب الگوی زمان‌بندی و بازیابی موجود بررسی شود.
- **هم‌زمانی کار**. CAT-01 و GM-01 پس از آغاز ممیزی SEO ظرفیت اجرای مستقل دارند. SEO-03 وابستگی تسکی صریح ندارد. برای شروع جریان اتصال داده، پذیرش خط مبنای P0 و دسترسی مجاز به Property به‌عنوان گیت برنامه لحاظ شده است. SEO-07/08 پس از زیرساخت SEO می‌توانند کنار جریان Growth پیش بروند. CX-02/03/04 و QA-01 به محض تحقق پیش‌نیاز می‌توانند مستقل جلو بیفتند. Checkout، Payment Events، Prisma Schema، Migration و قرارداد API مشترک مالک و ترتیب ادغام هماهنگ می‌خواهند.
- **تفسیر وابستگی‌ها**. `UrlInventory` ورودی SEO-06 از SEO-04 است. وابستگی فازی SEO-07/09 به تسک‌های تحویل‌دهنده آن فاز تبدیل شده است. SEO-10 به خروجی‌های پایدار P0–P4 متکی است و گراف زیر گیت‌های نهایی آن مسیرها را نشان می‌دهد. QA-02 تمام ۳۳ تسک Growth در P0–P6 را پوشش می‌دهد. QA-04 صراحتاً به GM-04 و CM-05 نیز وابسته است.
