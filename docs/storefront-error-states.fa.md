# SF-FINAL-06 — کنترل وضعیت‌های خطا

این کنترل برای سایت اصلی و پنل مدیریت انجام شود. وضعیت سفارش/پرداخت هرگز از query string
درگاه به‌تنهایی نتیجه‌گیری نمی‌شود؛ فقط سفارش تأییدشده در API می‌تواند «موفق» یا «ناموفق» باشد.

| سناریو                                         | رفتار مورد انتظار                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------------------- |
| نشانی اشتباه در Storefront یا Admin            | ۴۰۴ اختصاصی، لینک بازگشت، بدون صفحه پیش‌فرض Next.js؛ در صفحهٔ ناشناخته HTTP 404 |
| محصول حذف‌شده یا غیرفعال                       | متن «این محصول پیدا نشد» و مسیر بازگشت به کاتالوگ                               |
| قطع API هنگام مشاهده صفحه                      | صفحه خطای فارسی با تلاش دوباره؛ بدون نمایش جزئیات فنی                           |
| قطع API هنگام بررسی حساب checkout              | پیام اختلال سرویس؛ نباید به‌اشتباه ادعای انقضای نشست شود                        |
| نشست منقضی هنگام پرداخت                        | دعوت به ورود مجدد؛ حفظ اقلام سبد                                                |
| دسترسی ممنوع در پنل مدیریت                     | صفحه محدودیت دسترسی موجود؛ بدون نمایش محتوای عملیاتی                            |
| سبد قدیمی، کالای حذف‌شده یا موجودی تمام‌شده    | جلوگیری از ثبت/پرداخت مجدد و لینک بررسی سبد؛ سبد خودکار پاک نشود                |
| پاسخ ثبت سفارش یا شروع پرداخت نامشخص           | توقف تلاش دوباره و لینک بررسی سفارش‌ها؛ بدون ایجاد پرداخت جدید یا پاک‌کردن سبد  |
| callback نامشخص، پاسخ ناموجود یا قطع API سفارش | نمایش «در حال بررسی»، عدم صدور رویداد خرید و درخواست پیگیری سفارش               |
| تصویر عمومی مفقود                              | تصویر جایگزین محلی با alt محصول؛ صفحه همچنان قابل استفاده                       |
| خطای لایهٔ ریشه یا dashboard پنل               | صفحه فارسی با گزینه تلاش دوباره، بدون token، stack trace یا خطای خام            |

ابتدا `pnpm storefront:test`، `pnpm admin:test`، `pnpm storefront:typecheck`،
`pnpm admin:typecheck` و build هر دو برنامه را اجرا کنید. برای سناریوهای مرورگر،
`pnpm storefront:test:e2e` را اجرا کنید. در staging علاوه بر آزمون خودکار، مسیرهای اشتباه،
قطع موقت API و بازیابی آن، نشست منقضی و پاسخ نامشخص درگاه را به‌صورت دستی بررسی کنید.

در App Router، صفحه‌ای که `notFound()` را در پاسخ streamشده صدا می‌زند ممکن است با HTTP 200
به مرورگر برسد، ولی رابط ۴۰۴ و متای `noindex` دارد. در مقابل، نشانی کاملاً نامعتبر باید با
HTTP 404 برگردد. کنترل خطاهای HTML صفحات، جایگزین کنترل جداگانهٔ پاسخ‌های ۴۰x/۵۰x API نیست.

`globalNotFound` در Next.js 16 هنوز experimental است؛ این مسیر برای URL کاملاً ناشناخته،
مستقل از layout و سرویس API صفحهٔ ۴۰۴ را تولید می‌کند. نتیجه را در build و staging هم کنترل کنید.
